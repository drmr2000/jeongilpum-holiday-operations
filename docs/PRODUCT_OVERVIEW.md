# 제품 개요

## 목적

정일품 운영 웹앱은 고객 주문을 수령·배송·현장판매 작업으로 분해하여 판매장과 작업장이 같은 D1 데이터를 처리하도록 구성한 상시 운영 시스템입니다.

## 사용자

- 고객: 고정된 키오스크 흐름에서 상품 또는 맞춤주문을 접수합니다.
- 판매장 운영자: 수령일시별 작업, 고객 도착, 주문 확인, 결제 상태와 미수 현황을 관리합니다.
- 작업장 운영자: 현장예약·택배 작업의 준비 상태와 상품별 수량을 관리합니다.
- 생산·패키지 담당자: 생산 batch, Skin Pack, package, 이력 정보를 관리합니다.
- 상품 담당자: 설정 화면에서 상품과 일일 한정수량을 편집합니다.

## 운영 단위

`work_items`의 한 행은 고객, 상품, 수령일시, 수령방법, 수령자를 연결한 작업 단위입니다. 한 주문은 여러 `work_items`를 가질 수 있고, 주문의 결제 상태와 금액은 `orders`에서 공통으로 관리합니다.

수령방법은 다음 값입니다.

- `onsite_sale`: 현장판매
- `onsite_reservation`: 현장예약
- `delivery`: 택배예약

현장판매는 주문 시점의 `due_at`을 사용하며 `completed`, `paid` 상태로 즉시 생성됩니다.

## 핵심 흐름

```text
고객 주문
→ orders와 work_items 생성
→ 판매장 작업 테이블에서 확인·도착·결제 처리
→ 작업장에서 현장예약 또는 택배 준비
→ 생산·Skin Pack·package 부가 기능 처리
→ work_item_events에 변경 이력 보존
```

## 제품 원칙

- D1 `DB`가 운영 데이터의 단일 원본입니다.
- 고객 주문은 공개 API로 접수하고, 운영 데이터 변경은 운영 세션으로 제한합니다.
- 결제는 PG 연동 없이 운영자가 `unpaid`, `partial`, `paid`와 입금액을 수동으로 수정합니다.
- 취소된 작업은 목록 집계에서 제외하되 이력은 `work_item_events`에 남깁니다.
- 작업 행을 삭제해도 `work_item_events.work_item_id`는 `NULL`로 전환되고 `order_id` 이력은 유지됩니다.
- core schema는 작업장 부가 테이블을 외래 키로 참조하지 않습니다. 다만 작업 삭제 API는 외래 키 정리를 위해 연결 package와 Skin Pack 배정을 함께 처리합니다.

## 상시 운영과 예약 범위

판매기간이나 시즌 테이블은 없습니다. 키오스크 달력은 오늘부터 365일까지만 표시하기 위해 코드 상수의 범위를 사용합니다. 이 범위는 상품 설정이나 운영 설정에서 변경하지 않습니다.

## 명시적 비범위

- PG·카드사 승인 연동
- 고객 장부 전용 테이블과 별도 장부 API
- SMS·카카오 알림 발송
- Supabase, Postgres, Vercel
- 상품 이미지 업로드 저장소
- 프린터 또는 Open Label API 직접 제어

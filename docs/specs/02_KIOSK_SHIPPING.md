# 고객 메인화면 수정 02: 택배발송 / 주소 / 발송일

## 중요도
P0.
주소 오류는 실제 오배송으로 이어질 수 있으므로 UI 편의보다 데이터 정확성을 우선한다.

---

# 1. 도로명주소 검색 문제 수정

현재 증상:
- 도로명주소 본문은 맞지만
- 괄호 안 참고정보가 실제 주소와 맞지 않는 경우가 있음

## 원칙
배송주소 원본에 **참고항목 문자열을 강제로 합치지 않는다.**

정부 도로명주소 API 계열 필드 기준:
- roadAddrPart1 = 참고항목 제외 도로명주소
- roadAddrPart2 = 참고항목
- jibunAddr = 지번주소
- zipNo = 우편번호
- addrDetail = 고객 입력 상세주소

### 실제 배송주소 저장
기본:
`roadAddrPart1 + addrDetail`

예:
- roadAddrPart1: 전라남도 고흥군 고흥읍 ...
- addrDetail: 101동 1203호

### 별도 저장 가능
- road_addr
- road_addr_reference
- jibun_addr
- postal_code
- detail_addr

`roadAddrPart2`는 화면 참고용으로만 사용하고,
택배송장 기본주소 문자열에 무조건 붙이지 않는다.

---

# 2. 주소 검색 UI

## 권장 1순위
정부 주소정보누리집/도로명주소 검색 API를 안정적으로 사용.

검색결과 카드:
- 도로명주소
- 지번주소(보조)
- 우편번호

예:

```text
[06164]
서울특별시 강남구 테헤란로 123
지번: 서울특별시 강남구 역삼동 ...
[이 주소 선택]
```

괄호 참고항목은 필요하면 작은 보조정보로만 표시.

---

# 3. 직접입력 fallback

주소검색이 실패하거나 고객이 원하는 주소가 검색되지 않으면
**직접입력 기능을 반드시 제공한다.**

버튼:
`주소를 직접 입력할게요`

직접입력 필드:
- 우편번호(선택 또는 검색)
- 시/도
- 시/군/구
- 도로명/지번 주소
- 상세주소

단, 자유입력 주소는 최종확인에서 크게 재확인시킨다.

표시:
`직접 입력한 주소입니다. 배송 전 주소를 다시 확인해주세요.`

---

# 4. 주소 최종확인

주문 최종 접수 직전:

```text
받는 분
홍길동 010-1234-5678

배송주소
[06164]
서울특별시 강남구 테헤란로 123
101동 1203호

[주소 수정]
```

고객이 실제 택배에 쓰일 주소를 눈으로 다시 확인해야 한다.

---

# 5. 발송 날짜 선택 추가

현재 발송일 필드가 없어 주문 접수가 차단되는 문제를 수정.

택배발송 flow에 **발송 희망일/발송 예정일 선택 단계**를 반드시 추가한다.

## 위치
권장:
1. 보내는 분
2. 받는 분
3. 주소
4. 발송 날짜
5. 최종 확인

## 날짜 선택
방문수령과 같은 Calendar component 재사용 가능.

단 배송일은:
- 오늘 이전 금지
- 휴무일/발송불가일 disable
- 시즌 배송 가능 기간 사용
- 마감일 disable

사용자 문구:
`상품을 발송할 날짜를 선택해주세요.`

주의:
이 값은 **도착보장일이 아니라 발송 예정일**임을 명확히 한다.

예:
`택배사 사정에 따라 도착일은 달라질 수 있습니다.`

# 6. DB 필드 검증

fulfillment.type = shipping이면
주문 confirm 전 반드시:
- recipient_name
- recipient_phone
- road/address
- detail address (필요한 경우)
- postal code
- ship_date

검증.

현재 `ship_date`가 null이라 주문 접수가 안 되는 구조라면:
- UI에서 필수 입력
- 서버에서도 validation
- DB constraint/RPC validation 확인

---

# 7. 서버 validation

클라이언트 validation만 믿지 않는다.

shipping 주문:
- ship_date required
- recipient required
- valid address string required
- postal_code 권장 required
- sender info required

오류 시:
- 주문완료 화면 금지
- 기존 입력값 유지
- 어떤 필드가 부족한지 정확히 안내

---

# Acceptance Criteria
1. 도로명주소와 참고항목 분리.
2. 실제 배송주소에 잘못된 괄호정보 강제삽입 없음.
3. 지번주소를 보조 확인 가능.
4. 직접주소입력 fallback 있음.
5. 상세주소 입력 가능.
6. 최종확인에서 실제 배송주소 크게 표시.
7. 발송 날짜 선택 단계 있음.
8. ship_date 없이 주문 제출 불가.
9. 올바른 ship_date 입력 시 주문 정상 접수.
10. 주소검색 실패해도 직접입력으로 주문 가능.
